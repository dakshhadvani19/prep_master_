# PrepMaster — Codebase Guide

This file is a concise current guide. The authoritative detailed context is in docs/PREPMaster_PROJECT_CONTEXT.md and the implementation snapshot is in docs/PREPMaster_CURRENT_STATUS.md.

## Runtime layers

1. React/Vite application
2. Supabase Auth and Postgres
3. Vercel serverless endpoints for protected server-side operations
4. Browser-local/static adapters for unfinished persistence

## Catalog

Departments are static in src/data/catalogDomains.js.
Courses, course semester options, Subjects, and subject semesters are read from Supabase.
courseMapping.json and subjectIdBridge.json are compatibility data, not replacements for runtime catalog fields.

## Authentication

Supabase Auth is the only identity provider. AuthContext owns session state and role routing. OTP is generated/verified by serverless endpoints against public.auth_otp.

## Exam flow

ExamPortal resolves the selected subject, prepares questions, runs the exam, and stores a compact result through src/utils/examHistoryStorage.js until persistent attempts are migrated.

## Syllabus flow

SyllabusAdmin extracts PDF text locally and stores metadata/text in src/utils/syllabusStorage.js until persistent Supabase storage is designed.

## Temporary persistence

Local adapters are intentionally explicit. They do not add fake network waits and must not be described as durable server-side persistence.

## Security

RLS is authoritative. Service-role credentials remain server-only. Client storage is never an authorization source.

## Removed architecture

The former secondary backend and its browser SDK/configuration are no longer part of this repository. Do not reintroduce them to solve unfinished persistence.
